## Rendus adaptés
Les diapos de chaque cours sont compilées en plusieurs rendus, à partir des mêmes sources ; la charte commune
(`commun/charte.typ`) applique la variante choisie à la compilation. Le rendu de projection sert en cours ;
les autres se téléchargent, pour lire les diapos dans le rendu qui convient à sa vision ou à sa lecture.

| Variante | Fichier | Pour qui, quoi |
|---|---|---|
| projection | `<cours>-projection.pdf` | La projection en cours, pour la vision typique. |
| deuteranopie | `<cours>-deuteranopie.pdf` | Daltonisme rouge-vert, la forme la plus fréquente : le vert devient bleu-vert, bien distinct de l’orange et du bleu. |
| protanopie | `<cours>-protanopie.pdf` | Daltonisme rouge-vert (insensibilité au rouge) : même palette que la deutéranopie. |
| tritanopie | `<cours>-tritanopie.pdf` | Confusion bleu-vert et jaune-violet : le vert devient violet. |
| achromatopsie | `<cours>-achromatopsie.pdf` | Vision sans couleur : les couleurs se distinguent par leur clarté. |
| dyslexie | `<cours>-dyslexie.pdf` | Lettres, mots et lignes plus espacés ; pas de capitales forcées ni d’italique. |

Les palettes sont vérifiées par simulation de chaque type de vision, et chaque rôle pédagogique porte aussi
un pictogramme (voir [`commun/README.md`](commun/README.md)). Chaque variante s’ouvre sur une page « Légende »
qui relie ses couleurs à celles de la projection.

## Organisation
Un dossier par cours, et dans chaque cours un dossier par nature de support. Les pages web renvoient les unes
aux autres : un TP vers la diapo qui porte la notion et vers l’artefact qui la fait manipuler.

- `<cours>/cm/` : le cours magistral. `<cours>.typ` contient les diapos, en [Typst](https://typst.app) avec
  [Touying](https://github.com/touying-typ/touying) ; les PDF `<cours>-<variante>.pdf` sont compilés par la CI.
  Un exercice fait et corrigé en séance reste dans les diapos.
- `<cours>/tp/<tp>/` : une séance de travaux pratiques. `<tp>.typ` contient l’énoncé, compilé par la CI en page
  web `index.html` ; `corrige/` contient les corrigés, fichiers réels que l’énoncé affiche à la demande ;
  `tester.sh` les construit et les vérifie.
- `<cours>/artefacts/<nom>/` : un artefact, petit logiciel interactif qui fait manipuler un concept.
  `<nom>.typ` le présente, `<nom>.js` et `<nom>.css` le font vivre ; la CI en tire une page web `index.html`.
- `commun/` : la charte partagée (rôles, palettes, thème des diapos, thème des pages web) et les polices
  IBM Plex ; voir [`commun/README.md`](commun/README.md). `commun/terminal/` : le terminal des pages web (VM dans
  le navigateur, compagnon relié au shell de l’étudiant) et sa page [Le compagnon du terminal](https://jmchantrein.github.io/Cours/commun/terminal/).
- `index.typ` : la page d’accueil du site, compilée en `index.html` ; elle range les sept cours par groupes, du plus
  fondamental au plus avancé (le tableau ci-dessus suit le même ordre).

## Compiler
Typst 0.15 ou plus récent, depuis la racine du dépôt (Touying se télécharge seul à la première compilation).
Les diapos :

    typst compile --root . --font-path commun/fonts virtualisation/cm/virtualisation.typ build/virtualisation.pdf
    typst watch   --root . --font-path commun/fonts virtualisation/cm/virtualisation.typ build/virtualisation.pdf

Pour une variante : ajouter `--input variante=<variante>` (par exemple `--input variante=dyslexie`).

Une page web (TP, accueil) : l’export HTML de Typst est encore expérimental, d’où `--features html` ;
la version de Typst est fixée dans la CI.

    typst compile --root . --font-path commun/fonts --features html --format html conteneurisation/tp/wordpress/wordpress.typ build/wordpress.html

Le terminal des pages web (bouton « Exécuter » à côté des commandes) a besoin de fichiers tiers, préparés à part :

    commun/terminal/preparer.sh --vm              # xterm.js, v86, image de la VM (Docker)
    commun/terminal/compagnon/construire.sh       # exécutables du compagnon (Go)

Tout le site d’un coup (terminal, PDF des six variantes, pages web), à leur place dans l’arbre : c’est ce que lance la CI.

    commun/construire-site.sh [dossier]           # défaut : ce dépôt ; Typst, Docker, Go, Node et Python 3 requis
    COURS_VARIANTES="projection dyslexie" commun/construire-site.sh     # moins de variantes, pour aller plus vite

Le script ne fait une étape que si l’arbre la demande (sans `commun/terminal/`, pas de terminal) : il construit aussi
bien un arbre ancien que le courant.

`--root .` autorise l’import de `commun/`. Les fichiers générés ne sont pas versionnés : git ignore `build/`,
les PDF de `<cours>/cm/`, les `index.html`, `commun/terminal/vendor/` et `commun/terminal/compagnon/dist/`. Pour suivre les liens d’une page web à l’autre, compilez-la à sa
place, à côté de sa source (`…/wordpress/index.html`).

Sur GitHub, l’action `.github/workflows/compilation-cours.yml` appelle `commun/construire-site.sh` à chaque push sur `main`
touchant les sources ou la charte, et publie le résultat sur le site, sans rien commiter.
L’action `.github/workflows/test-corriges.yml` lance le `tester.sh --up` de chaque TP, un harnais par tâche
(la matrice est la liste des `*/tp/*/tester.sh`) : chaque TP a son résultat, et les durées ne s’additionnent pas.

Ajouter un cours : créer `<cours>/cm/<cours>.typ` qui importe `../../commun/theme-cours.typ`, puis l’ajouter à
`index.typ` (carte, avec son illustration de couverture) et au tableau ci-dessus.
Ajouter un TP : créer `<cours>/tp/<tp>/<tp>.typ` qui importe `../../../commun/theme-tp.typ`, avec ses corrigés
dans `corrige/` et, s’ils s’exécutent, un `tester.sh` (la CI le découvre seule).

Conventions des harnais `tester.sh` :

- **Paquets du système.** Un harnais qui demande des paquets `apt` sur la machine qui le lance (ceux que les autres
  installent dans des conteneurs) les déclare dans `paquets-apt.txt`, à côté de lui : un nom par ligne, `#` pour un
  commentaire. La CI les installe avant de le lancer. Exemple : `virtualisation/tp/libvirt/paquets-apt.txt`.
- **Proxy qui réécrit TLS.** Seule la variable `TPTEST_CA` en tient compte ; elle est facultative, et absente en CI.
  Derrière un tel proxy, `TPTEST_CA=/chemin/ca.crt HTTPS_PROXY=http://hôte:port ./tester.sh --up` fait passer les
  conteneurs et les constructions d’images par `HTTPS_PROXY` (réseau de l’hôte), avec cette autorité de certification
  pour apt et apk. `TPTEST_CA` sans `HTTPS_PROXY` est une erreur. Sans `TPTEST_CA`, le harnais ignore `HTTPS_PROXY` et
  `SSL_CERT_FILE` et se comporte comme en CI.

## Site
Le site est le dépôt, complété des supports compilés : l’action de compilation dépose l’ensemble sur
<https://jmchantrein.github.io/Cours/> par GitHub Pages (source « GitHub Actions »).
`index.html` mène aux diapos, aux TP et aux artefacts. Chaque page web embarque les variantes de rendu, que le lecteur
choisit dans la page.

### Aperçu d’une branche
Le workflow lancé à la main sur une branche autre que `main` publie cette branche sous
<https://jmchantrein.github.io/Cours/apercu/>, sans toucher à la production : la racine du site reste celle de `main`,
reconstruite. Depuis l’onglet Actions (« Compilation et publication des supports », *Run workflow*, choisir la
branche) ou par :

    gh workflow run compilation-cours.yml --ref <branche>

Le résumé de la tâche donne l’adresse et le nom de la branche ; chaque page web de l’aperçu porte, dans son bandeau,
« Aperçu de la branche … — ce n’est pas le site publié ». Cet aperçu est public. Il est éphémère : la publication
suivante (push sur `main` ou autre aperçu) l’efface, et il n’y en a qu’un à la fois. Les liens absolus
vers `https://jmchantrein.github.io/Cours/…` et vers l’archive de `main` (commandes `curl … | tar` des TP) mènent à la
production, non à l’aperçu. Si l’environnement `github-pages` limite les branches autorisées à déployer, y ajouter
la branche (Settings, Environments).
